# Chapter Authoring — 챕터 집필 스킬

JS 숙련 개발자에게 Python을 가르치는 챕터를 쓰는 방법. 형식은 `assets/chapter-template.md`를 복사해서 시작한다.

## 서술 원리

**독자 모델을 고정하라:** 독자는 map/filter/클로저/프로토타입을 설명 없이 이해하는 시니어 JS 개발자다. 따라서 (1) JS 개념 설명은 0줄, (2) 모든 새 개념은 "JS에서 알던 것"에 접붙이고, (3) 대응이 없는 Python 고유 개념만 바닥부터 설명한다. 이 원칙이 무너지면 책 분량이 2배가 되고 독자는 아는 내용을 건너뛰다 함정 콜아웃까지 놓친다.

**비교는 나란히:** 개념 도입부는 반드시 JS/Python 코드를 나란히 보여준다. 마크다운 표 2열 형식을 쓴다 (조판 시 좌우 비교 레이아웃으로 렌더링됨):

````markdown
| JavaScript | Python |
|---|---|
| ```const nums = [1, 2, 3];```<br>```const doubled = nums.map(n => n * 2);``` | ```nums = [1, 2, 3]```<br>```doubled = [n * 2 for n in nums]``` |
````

단, 표 안의 코드는 실행 검증이 안 되므로 3줄 이하 스니펫만 허용한다. 그보다 긴 예제는 표 대신 "JavaScript" / "Python" 소제목 아래 별도 코드 블록으로 나란히 배치한다.

## 코드 블록 규칙 (검증 파이프라인과의 계약)

- 모든 ` ```python ` 블록은 code-verifier가 **위에서 아래로 같은 네임스페이스에서 순차 실행**한다. 따라서 챕터 내 앞 블록에서 정의한 변수를 뒷 블록에서 써도 된다 — 오히려 권장 (반복 정의 감소).
- 실행하면 안 되는 블록(에러 시연, 의사코드, 설치 명령)은 ` ```python no-run ` 펜스를 쓴다. 에러를 **시연**하는 게 목적이면 no-run 대신 try/except로 감싸 실행 가능하게 만드는 쪽을 우선한다 — 독자가 복붙해도 안전하다.
- 출력을 보여줄 때는 코드 블록 안에 `# 출력: ...` 주석으로 붙인다. 검증 스크립트가 이 주석과 실제 출력을 대조한다 (앞부분 일치 방식). 장황한 출력은 첫 줄만 적는다.
- JS 코드 블록(` ```javascript `)은 자동 검증되지 않는다. 현대 JS(ES2020+)로 쓰고, var·콜백 스타일 금지 — qa-reviewer가 검사한다.

## 필수 구성 요소 (챕터당)

| 요소 | 규칙 |
|------|------|
| 학습 목표 | 챕터 서두에 3~5개, "~할 수 있다" 형식 |
| JS 함정 콜아웃 | `> ⚠️ **JS 함정**: ...` — js-python-mapping.md의 "함정" 표에 해당하는 개념이 나오면 반드시 삽입 |
| AICE 연결 콜아웃 | `> 🎯 **AICE**: ...` — 이 문법이 시험에서 어떻게 쓰이는지. 연관도 '상' 챕터는 필수 |
| 연습문제 | 챕터 말미 2~4문항. AICE 형식을 따라 **빈칸 채우기형** 우선. 정답은 `<details>` 접기 안에 |
| 요약 표 | 챕터 말미 "이 챕터의 JS→Python 대응 한눈에 보기" 표 |

## 문체

- 경어체("~합니다")로 통일한다. 콜아웃·주석 안에서도 동일.
- 용어는 첫 등장 시 "한글(영문)" 병기 후 한글로 통일: 딕셔너리(dict), 리스트(list), 튜플(tuple). "사전", "배열"이라 부르지 않는다 — 배열은 NumPy array 전용.
- 한 문단 3문장 이내. 설명이 길어지면 코드로 보여준다.

## 분량

챕터당 본문 150~350줄 (연습문제 포함). 350줄을 넘기면 개념을 다 못 다뤄서가 아니라 설명이 장황한 것이다 — 코드 위주로 압축하라. 커리큘럼의 개념 목록을 다 다뤘는지가 완성 기준이며, qa-reviewer가 교차 검증한다.
